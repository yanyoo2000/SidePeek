# SidePeek · 侧边抽屉速览

> **点视频不再丢页面 —— 右侧溜一眼，看完就关。**

一个 Chrome 扩展：在哔哩哔哩任意页面点击视频链接时**不跳转**，而是从右侧滑出一个抽屉，抽屉里是完整的视频页 —— 能播放、有弹幕、有评论。关掉抽屉，原来的页面（滚动位置、搜索结果、筛选条件）一点没变。

*↑ 真实 Chrome 加载已解压扩展后的截图：左侧搜索页保持原样，右侧抽屉里视频正在播放。*

## 为什么做它

| 痛点 | 现实 | SidePeek 之后 |
|---|---|---|
| **刷首页推荐**，点开一个不感兴趣的，回来推荐流已重排/回到顶部 | 只能开一堆新标签页，最后一并关掉 | 关掉抽屉，还在原来那一屏 |
| **搜东西**时想快速比对多个结果 | 每点一个就离开搜索页，后退回来筛选条件常丢 | 在抽屉里连开三个，搜索词/页码不动 |
| **看视频时**点右侧相关推荐 | 一离开就丢进度、丢评论区楼层 | 抽屉里看一眼，不打断当前视频 |

## 核心特性

1. **点击即预览**：B 站首页、搜索页、视频页里的视频链接，点一下从右侧滑出抽屉，不离开当前页面。
2. **完整视频页**：抽屉里不是"精简播放器"，而是真正的 B 站视频页 —— 播放、弹幕、评论、相关推荐都在。
3. **关掉就还原**：原页面滚动位置、搜索结果、筛选条件完整保留，没有多余的刷新和跳转。
4. **后退键符合直觉**：按浏览器后退 = 关抽屉；再按前进 = 抽屉重新打开（用了 History API 记账）。
5. **宽度记得住**：拖抽屉左边缘调宽，下次打开还是这个宽度（存在本机）。
6. **跨源也不被弹走**：从 `search.bilibili.com` 内嵌 `www.bilibili.com` 视频页时，B 站的防嵌入逻辑无法把整个页面顶走。
7. **零依赖、最小权限**：不引第三方库、不申请标签页/网络拦截等多余权限，只存一个宽度值。
8. **三种关闭方式**：右上角 ×、按 Esc、点左侧灰掉的遮罩；还能双击标题把抽屉铺满全屏。

## 30 秒上手

1. **拿到代码**：`git clone https://github.com/yanyoo2000/SidePeek.git`
   （或直接下载 ZIP 解压）
2. **打开扩展管理页**：地址栏输入 `chrome://extensions` 回车
3. **打开开发者模式**：右上角「开发者模式」开关拨到开启
4. **加载扩展**：点左上角「加载已解压的扩展程序」→ 选择项目文件夹（`SidePeek` 或解压得到的 `SidePeek-main`，**即含 `manifest.json` 的那一层**，不是它的上级目录）

装好后打开任意 B 站页面（**已经打开的标签页请按 F5 刷新一次**），点一个视频试试。

> 需要 Chrome **102 或更高版本**。不需要 `npm install`，安装扩展不需要构建步骤。

## 交互速查表

| 想做什么 | 怎么做 | 会发生什么 |
|---|---|---|
| 打开预览 | 单击视频卡片 / 视频标题链接 | 抽屉从右侧滑出，加载视频页 |
| 换一个视频 | 抽屉开着时，再点另一个视频链接 | 抽屉保持展开，只换内容（不重播入场动画） |
| 关闭 | 右上角 **×** / 按 **Esc** / 点左侧灰掉的遮罩 | 抽屉滑回右侧，原页面复原 |
| 用后退键关 | 浏览器「后退」 | 抽屉关闭，页面不跳走 |
| 重新看上一个 | 浏览器「前进」 | 抽屉按上次的视频重新打开 |
| 调宽度 | 鼠标移到抽屉**左边缘**（出现蓝色细条）→ 按住左右拖 | 实时跟随，松手后记住宽度 |
| 铺满屏幕 | **双击抽屉顶部的标题** | 抽屉占满整个窗口；再双击还原 |
| 开完整页面 | 抽屉顶部 **↗**（在新标签页打开） | 新标签页打开这个视频 |
| 复制视频地址 | 抽屉顶部 **复制链接** | 底部弹出「链接已复制」 |
| 保留浏览器行为 | 按住 **Ctrl / ⌘ / Shift / Alt** 再点，或用**鼠标中键**点 | 不拦截，按浏览器默认方式新标签打开 |

**没有全局快捷键**，也不需要记：只有 Esc 一个键，且只在焦点还没进入抽屉内的视频区域时有效（见下方已知限制）。

## 它是怎么做到的

三句话，给技术读者：

1. **右侧抽屉是个覆盖层**：注入到 B 站页面里的 Shadow DOM 宿主用 `position:fixed` 铺满视口、`pointer-events:none`，只有抽屉自身和遮罩吃事件 —— 所以它纯覆盖、不挤压原页面，关闭态对页面零影响，样式也互不污染。
2. **挡住 frame-buster 靠的是受限 sandbox**：抽屉里用 `<iframe sandbox>` 承载视频页，但**故意不含** `allow-top-navigation` —— B 站视频页想把自己"顶"到顶层时会被浏览器拒绝，这是跨源场景（`search.bilibili.com` 内嵌 `www.bilibili.com`）能成立的关键；该属性在创建时定死，另有 MutationObserver 盯着，被外部改写会立刻恢复。
3. **后退键的语义靠 History API 记账**：打开抽屉时 `pushState` 一条 `#sidepeek=<视频地址>` 记录（抽屉内切换视频用 `replaceState` 不叠记录），`popstate` 是唯一的收起/展开权威 —— 于是"后退 = 关抽屉、前进 = 重开抽屉"是浏览器原生行为，不需要额外拦截。

细节见 [docs/SPEC.md](docs/SPEC.md)（接口契约与交互规格）与 [docs/TECH-FINDINGS.md](docs/TECH-FINDINGS.md)（真机实测结论）。

## 已知限制

v0.1.0 **只做一件事并且做完整**，以下限制是刻意的取舍，不是待修的 bug：

1. **只在哔哩哔哩域名生效**（`*.bilibili.com`）。其他网站点击视频链接，没有任何变化。
2. **抽屉内不能再弹出抽屉**：在抽屉里点别的视频，是在抽屉内部导航（刻意设计，避免"抽屉套娃"）。
3. **Esc 在焦点进入视频区域后失效**：点到播放器/评论区后，键盘焦点进了抽屉里的页面，顶层收不到 Esc；此时请用右上角 × 或点遮罩关闭。
4. **抽屉固定深色皮肤**，不跟随系统亮色/暗色（v0.1 有意为之，已书面豁免）。
5. **需要 Chrome 102 及以上**（用到了 `inert` 属性做键盘可达性隔离）。
6. **宽度只能用鼠标拖动左边缘调整**，暂不支持键盘调宽。
7. **连点去抖未实现**：极短时间内连续点多个视频，可能看到几次加载闪烁（正常速度点击不受影响）。
8. **抽屉内翻过页后可能出现"后退要按两次"**：在抽屉里继续点视频会让浏览器历史里增加子记录，这是浏览器自身行为；关闭抽屉本身仍是一次点击即可。
9. **个别页面「前进重开抽屉」可能不生效**：B 站是单页应用，会在 `popstate` 里自行改写历史，某些情况下会把"前进"目标剪掉。真机回归（首页 / 搜索结果页）未复现，但若你遇到，刷新页面重新点一次即可。这是站方行为，不是扩展能控制的。
10. **不申请标签页权限**：扩展无法自动操作/切换标签页；「在新标签页打开」按钮只是打开链接。
11. **视频不会自动播放**：受浏览器自动播放策略限制，需要在抽屉里点一下播放。
12. **B 站改版可能导致失效**：页面结构变化后，链接拦截或加载可能失灵，届时需更新扩展。
13. **非官方工具**，与哔哩哔哩无任何关联；不收集任何用户数据，不发送任何统计。

## 开发与测试

需要 **Node.js ≥ 22**（`node --test` 与真机联调脚本）。扩展本身零依赖、无构建步骤。

```bash
npm test          # 单元测试 + CSS 一致性校验
npm run test:unit # 只跑单元测试
npm run test:css  # 只校验 peek-drawer.css 与 JS 内嵌 CSS 是否逐字一致
npm run test:real # 真实 Chrome：加载未打包扩展，断言 18 项核心链路（自建临时 profile）
npm run test:all  # test + test:real
```

- 真机联调脚本会用 CDP 的 `Extensions.loadUnpacked` 加载当前目录，验证"扩展作为扩展能装上"，
  这是注入式测试覆盖不到的一层；证据见 [docs/T7-REAL-EXTENSION.md](docs/T7-REAL-EXTENSION.md)。
- 改了 `src/core/peek-drawer.css` 必须同步改 `peek-drawer.js` 里的 `CSS_TEXT`，否则 `npm run test:css` 会失败。
